## 一、远程节点同步（多节点 Tag 冲突修复）

### 问题
中央面板添加远程节点后，日志报错 `UNIQUE constraint failed: inbounds.tag`，导致部分远程入站同步不到本地。

### 原因
入站的 tag（如 `inbound-41883`）原先是全局唯一的。如果本地面板和远程节点都有端口 41883 的入站，它们会生成相同的 tag，写入数据库时报唯一冲突。

### 改动
把 tag 的约束从"全局唯一"改成 "(tag, node_id) 联合唯一"，不同节点的入站可以同 tag 共存，互不干扰。

| 文件 | 改动内容 |
|------|----------|
| `database/model/model.go` | Tag 约束改为联合索引 `idx_tag_node` |
| `database/db.go` | 新增 `migrateInboundIndexes()`，启动时删除旧索引 |
| `web/service/inbound.go` | 同步代码 key 从 `tag` 改为 `(tag, nodeID)` |
| `web/service/port_conflict.go` | 本地 tag 生成不再被远程 tag 干扰 |

### 回退
1. 把 `model.go` 的 Tag 和 NodeID 标签改回原来的 `unique` 和 `index`
2. 删除 `db.go` 中的 `migrateInboundIndexes()` 及调用
3. 把 `inbound.go` 的 `centralKeys` 改回 `tagToCentral`
4. 把 `port_conflict.go` 的 `tagExists` 去掉 `AND node_id IS NULL`
5. 重新编译部署

### Protocol 列按 6 级排序
点击表格的「Protocol」列头，按以下优先级排序：
1. **协议类型**：vless > hysteria2 > hysteria > trojan > vmess > shadowsocks > http > tunnel > mixed > wireguard
2. **传输方式**：tcp > xhttp > grpc > httpupgrade > ws > kcp > http > udp（Hysteria）> none
3. **安全层**：Reality > TLS > 无
4. **ECH PQ 群组**：`tls.settings.echConfigList` 含 `ml-kem-768` > 含 `x25519` > 空
5. **MLDSA65**：`reality.settings.mldsa65Verify` 非空 > 空
6. **ECH 服务器密钥**：`tls.echServerKeys` 非空 > 空

## 三、聚合订阅系统（**新增功能**）

### 背景
旧版订阅系统每个客户端自动生成一个 subId（存储在 Inbound 的 Settings JSON 中），只能返回单个客户端配置。无法用一个链接聚合多个入站的多个客户端。

### 新系统设计
新建 `subscriptions` 表，管理员手动创建订阅，选择要包含的入站列表（入站可拖拽排序），生成唯一的 subId 作为订阅链接。

#### 后端数据模型（`database/model/model.go`）

```go
type Subscription struct {
    Id                    int
    SubId                 string  // 随机 16 位 base62
    Enable                bool
    Format                string  // text | base64 | json | clash
    Password              string
    InboundIds            string  // 逗号分隔，顺序即输出顺序
    ExpiryTime            int64   // 0 = 永不过期
    ShowInfo, EmailInRemark bool
    Title, SupportUrl, ProfileUrl, Announce string
    UpdateInterval        int
    Remark                string
    SyncWithInboundOrder  bool    // 始终按入站列表排序
    AutoIncludeAllEnabled bool    // 始终包含所有启用入站
    LastUsedAt            int64
    CreatedAt, UpdatedAt  int64
}
```

#### 后端新增文件/改动

| 文件 | 改动 |
|------|------|
| `database/model/model.go` | +Subscription struct |
| `database/db.go` | +AutoMigrate Subscription |
| `web/service/subscription.go` | **新建** CRUD + GetByInboundId + UpdateLastUsedAt + RemoveInboundId |
| `web/controller/subscription.go` | **新建** 6 个端点 |
| `web/controller/api.go` | +路由注册 |
| `sub/subController.go` | `subs()` 先查聚合订阅再回退旧版。`tryAggregateSub` 新函数，含 `recover()` 防 panic、按 sub.Format 输出、Sync/Auto 处理 |
| `sub/sub.go` | +设置 subscriptionService |
| `web/controller/inbound.go` | +checkSubscriptions + forceDelInbound 端点，修改 setInboundEnable 返回订阅引用 |

#### 订阅 URL 格式
```
{subURI}{subId}?pwd={password}
```

`subURI` 从面板设置读取（由 `subUriScheme/Address/Port/Path` 分段配置）。

#### 后端格式处理

`tryAggregateSub` 根据 `sub.Format` 决定输出：
- `text` → 原始 proxy links 纯文本
- `base64` → base64 编码（默认）
- `json` → JSON 封装
- `clash` → Clash YAML

不再受全局 `subEncrypt` 影响。`subEncrypt` 仅作为创建订阅时 `format` 的默认值。

#### 订阅过期处理
- `tryAggregateSub` 检查 `ExpiryTime`，过期返回错误
- 前端页面加载时自动检测过期订阅并调用 `setEnable(id, false)` 禁用
- 启用过期订阅时前端拦截并提示

#### 入站来源管理

| 开关 | 后端行为 |
|------|---------|
| `syncWithInboundOrder=true` | 按 `sort_order ASC, id ASC` 重排入站 ID 列表 |
| `autoIncludeAllEnabled=true` | 忽略 `inboundIds`，实时查询所有已启用入站 |

两个开关可同时开启：先 autoInclude（确定 IDs），再 syncWithInboundOrder（排序）。

#### 订阅链接浏览器访问
检测 `Accept: text/html` 时返回精美静态 HTML 页面（含订阅名称、格式、入站数、复制全部按钮、暗色模式自适应），curl 访问返回纯内容。

### 前端页面

#### 订阅列表页（`SubscriptionPage.vue`）
- 侧边栏"订阅"菜单项（在"节点"和"面板设置"之间）

## 十、链接生成规则统一（2026-05-17）

### 问题
后端订阅链接（text/base64/JSON/Clash）生成的地址和端口与前端"导出入站链接"不一致。配置了 externalAddr/externalPort 的入站，订阅链接使用了服务器监听地址而非对外地址。

### 修复
新增 `resolveAddress()` / `resolvePort()` 公共方法，统一地址/端口解析链：

```
地址优先级: externalAddr > Node.Address > Listen > 请求 host
端口优先级: externalPort > 0 ? externalPort : inbound.Port
```

5 个协议生成器统一调用上述方法。Shadowsocks 的 method/password 改用 `ok` 守卫 + settings 顶层/client 对象双重读取。

### 涉及文件
| 文件 | 改动 |
|------|------|
| `sub/subService.go:590-609` | +resolveAddress/resolvePort |
| `sub/subService.go:230-560` | 5 协议生成器统一替换 |

## 十一、后端客户端遍历优化 + 入站数统计修复

### `tryAggregateSub` 改为客户端级别 recover
- 之前：`recover()` 包裹整个入站，一个客户端 panic 跳过整个入站
- 现在：`recover()` 包裹每个 `GetLink` 调用，失败只跳过单个客户端

## 十五、修复：拖拽自动滚动方向反转-回滚（2026-05-17）

### 问题
订阅已选入站拖拽到上边缘后向上滚动，鼠标离开上边缘后**自动向下滚动**（回滚）。入站列表排序拖拽也存在同样逻辑，但因容器高度较大（~2000px）表现不明显。

### 根因：数学缺陷

当前参数：`trigger = h × 0.5`，`release = h × 0.65`

对于订阅表单的 `.inbound-list`（`max-height: 380px`）：
- `trigger = 190px`，`release = 247px`
- 上 trigger (`0~190px`) + 下 trigger (`190~380px`) = **正好铺满整个容器，不存在中立区**
- 释放点对侧距离 `botDist = 380 - 247 = 133px < trigger(190)` → 永远触发反向

**回滚序列（简化）**：
```
↑ 向上滚动中 (topDist=200 < release=247 → 继续↑)
→ topDist=250 > release=247 → scrollDir=0 (停)
→ botDist=130 < trigger=190 → scrollDir=1 ↓ 回滚！
```

### 三层防护修复

| 层 | 机制 | 效果 |
|----|------|------|
| ① 方向锁定 | 活跃滚动时只看同侧 release | 同一 `dragover` 事件内不落回对侧 |
| ② 空闲态缩 trigger | `idleTrigger = h × 0.3`（80~200px） | 容器中间 40% 区域是中立的 |
| ③ 对立区守卫 | release 时检查对侧是否在 idleTrigger 内 | 若在则不停止，继续原方向滚 |

### 参数对比

| | 改前 | 改后（空闲态） | 改后（活跃态） |
|---|---|---|---|
| 触发 | `trigger = h×0.5` | `idleTrigger = min(200, max(80, h×0.3))` | 不检查（已激活） |
| 释放 | `release = h×0.65` | — | `release = h×0.65` |
| 方向 | `if-else` 链式 | 方向锁定，只检同侧 | 方向锁定，只检同侧 |
| 中立区 | 0%（数学上不可能存在） | 40% 容器高度 | 依赖方向锁定 |

| 文件 | 改动 |
|------|------|
| `SubscriptionFormModal.vue:48-113` | `getSubScrollThresholds` 拆分为 `idleTrigger`/`release`；`onDragOver` 三层防护逻辑；`subScrollTick` 改用 `idleTrigger` |
| `InboundList.vue:422-536` | `getScrollThresholds` 同上拆分；`onRowDragOver` 三层防护；`scrollTick` 改用 `idleTrigger` |

## 十六、修复：subScrollTick 滚错容器（左侧→右侧）（2026-05-17）

### 问题
订阅已选入站拖拽到顶部附近后，右侧列表"跳到最末尾"。console 日志确认 `[DRAG_LARGE_JUMP]` 每次跳转的 `dragIdx → index` 不断增大（9→17、17→21、25→30……），同时 `scrollDir` 为 1（向下）。

### 根因

模板中有**两个** `.inbound-list`：
```html
<!-- ① 左侧"可用入站"——DOM 中第一个 -->
<div class="inbound-list">...</div>
<!-- ② 右侧"已选入站"——DOM 中第二个 -->
<div class="inbound-list" style="position:relative">...</div>
```

`getSubScrollThresholds()` 和 `subScrollTick()` 均使用 `document.querySelector('.inbound-list')`，返回的是**左侧**容器。而 `onDragOver()` 通过 `e.currentTarget.closest('.inbound-list')` 获取的是**右侧**容器。

**错误链条：**
```
左侧面板持续滚动 → 组件 layout 抖动 → @dragover 的 v-for index 错位
→ splice(dragIdx, 1) → splice(index, 0, item) 将 item 移到远处索引
→ 用户看到"整个列表跳到末尾"
```

### 修复

新增 `subScrollContainer` 模块变量，由 `onDragOver` 在每次事件中保存正确的右侧容器引用：

```javascript
let subScrollContainer = null; // 右侧容器引用

function onDragOver(e, index) {
  const container = e.currentTarget.closest('.inbound-list'); // ✅ 右侧
  subScrollContainer = container; // 保存供其他函数使用
  ...
}

function getSubScrollThresholds() {
  if (!subScrollContainer) return { idleTrigger: 120, release: 250 };
  const h = subScrollContainer.getBoundingClientRect().height; // ✅ 用右侧
  ...
}

function subScrollTick() {
  if (!subScrollContainer || subScrollDir === 0) return;
  subScrollContainer.scrollTop += subScrollDir * SUB_ROW_H; // ✅ 滚右侧
  ...
}

function resetSubScroll() {
  subScrollContainer = null; // 拖拽结束清空
  ...
}
```

### 文件改动

| 文件 | 改动 |
|------|------|
| `SubscriptionFormModal.vue:48-120` | 新增 `subScrollContainer`；三处使用 `document.querySelector('.inbound-list')` 改为使用 `subScrollContainer` |

### 回退
- 恢复 `getSubScrollThresholds` 和 `subScrollTick` 为 `document.querySelector('.inbound-list')`；删除 `subScrollContainer`

## 十七、rAF 逐像素平滑滚动 + InboundList 扩大触发区（2026-05-17）

### 问题
1. **订阅表单**：慢速滚动一顿一顿——每次 tick 跳一整个行高（34px），视觉上不是"滚"而是"跳"。
2. **入站列表**：靠近边缘还是感觉不到慢速——因为 idleTrigger 上限 200px，高大表格（50 条 ~2000px）里 200px 仅占 10%，加速度还没展开就已离开触发区。

### 方案

#### ① `setTimeout` + 跳行 → `requestAnimationFrame` + 逐像素

旧方案：
```javascript
setTimeout(scrollTick, delay);   // 跳行：容器.scrollTop += dir * ROW_H
```

新方案：
```javascript
scrollRAF = requestAnimationFrame(scrollTick);  // 每帧一次
function scrollTick(timestamp) {
  const delta = Math.min(timestamp - lastTs, 100); // 帧间时间差
  const pxPerMs = ROW_H / (300 + 5000 * t³);        // 当前像素速度
  container.scrollTop += dir * pxPerMs * delta;      // 逐像素移动
  scrollRAF = requestAnimationFrame(scrollTick);
}
```

每帧移动通常不到 2px（60fps 时），完全消除跳变感。

#### ② InboundList idleTrigger 上限 200 → 400

| 表格高度 | 旧 trigger（min 80, max 200） | 新 trigger（min 80, max 400） | 触发范围占比 |
|---------|------------------------------|------------------------------|------------|
| 500px | 150px | 150px | 30% |
| 1000px | 200px（被限） | 300px | 30% |
| 2000px | 200px（被限） | 400px（被限） | 20% |

高大表格的触发区从 10% 扩大到 20%，立方曲线有足够空间展开，慢速滚动可感知。

| 文件 | 改动 |

## 十八、纯位置驱动自动滚动（无状态机、无方向锁定）（2026-05-17）

### 背景
状态机模型（空闲 / 上滚 / 下滚 + 方向锁定 + 迟滞释放）存在多个问题：
1. 触发区狭小且被锁定态"困住"，快慢分界难以跨越
2. 鼠标离开触发区仍需跨越 release 阈值才停止，响应迟缓
3. 释放点必然触发对侧，回滚风险高

### 新方案：纯位置驱动
每次 `onDragOver` 独立判断鼠标当前距边缘距离，不与任何历史状态耦合：

```javascript
// 每次 onDragOver 执行一次：
let dir = 0;
if (topDist < idleTrigger) { dir = -1; scrollDist = topDist; }
else if (botDist < idleTrigger) { dir = 1; scrollDist = botDist; }

// rAF 执行器仅按最后的 dir 和 scrollDist 驱动滚动
scrollTick 中: container.scrollTop += dir * pxPerMs * delta;
```

| 条件 | 新行为 |
|------|--------|
| 鼠标在触发区内 | 立即按距离滚动（贴边 113 px/s，边界 6.4 px/s） |
| 鼠标离开触发区 | **下一帧即停** |
| 鼠标跨中线 | 方向立即切换，无迟滞 |

### 删除/保留清单

| 删除 | 保留 |
|------|------|
| `release` 阈值 | `idleTrigger`（h × 30%） |
| `scrollDir` 持久状态 | `scrollRAF` / `subRAF`（rAF 控制） |
| 方向锁定 if/else 链 | `scrollTick` rAF 执行器 |
| 对侧守卫 `botDist > idleTrigger` 等 | `subScrollContainer` 容器引用 |
| 迟滞释放逻辑 | `subScrollDist` / `scrollDist`（距离→速度） |

### 文件改动

| 文件 | 行 | 改前 | 改后 |
|------|---|------|------|
| `SubscriptionFormModal.vue` | 48-121 | 50行状态机 | 20行纯位置 |
| `InboundList.vue` | 422-540 | 50行状态机 | 20行纯位置 |

入站列表排序模式下，上下边缘无法触发慢速平滑滚动，直接快速滚动。

### 根因
```html
<a-table :scroll="{ x: 1000 }">  ← 只有 x，没有 y
```
ant-design v4 只在设置了 `scroll: { y: ... }` 时生成 `.ant-table-body`。没有 `y` 时，没有这个 div。所有依赖 `document.querySelector('.ant-table-body')` 的代码都空操作：

| 函数 | `querySelector('.ant-table-body')` | 后果 |
|------|-----------------------------------|------|
| `getScrollThresholds()` | null → 返回兜底 200px | 阈值计算了但无人引用 |
| `scrollTick()` | null → 立即 return | scrollTop 永远不执行 |
| `updateScroll()` | null → 立即 return | 方向/距离设了没意义 |
| 容器级 `addEventListener` | 目标为 null → 没挂上 | 事件黑洞仍在 |

### 修复：`findScrollContainer()` 三优先级查找

```javascript
function findScrollContainer() {
  // ① .ant-table-body（scroll.y 虚拟滚动表）
  const body = document.querySelector('.ant-table-body');
  if (body && (body.style.overflowY === 'auto' || body.style.overflowY === 'scroll')) return body;

  // ② #content-layout（InboundsPage 页面级滚动容器）
  const content = document.getElementById('content-layout');
  if (content && (content.style.overflowY === 'auto' || content.style.overflowY === 'scroll')) return content;

  // ③ 兜底
  return document.scrollingElement || document.documentElement;
}
```

同时将找到的容器缓存在 `scrollContainerEl` 中，避免每帧重复 DOM 查询。

| 文件 | 改动 |
|------|------|
| `InboundList.vue:441-450` | 新增 `findScrollContainer()` |
| `InboundList.vue:452-474` | `getScrollThresholds`、`scrollTick`、`updateScroll` 三处改用 `findScrollContainer` / `scrollContainerEl` |
| `InboundList.vue:420-431` | `onRowDragStart` 刷新 `scrollContainerEl` 并挂载容器级 handler |
| `InboundList.vue:560-566` | `removeTableBodyDragHandler` 使用 `scrollContainerEl` |

## 二十一、修复：拖拽行跳动 + 无法停止（先 scroll 后 reorder）（2026-05-17）

### 问题
入站列表拖拽行会来回跳动，拖拽行没法紧跟着鼠标；下边缘触发后无法停止。

### 根因：反馈循环

```
① @dragover → rowReorderById(X,Y) → Vue 重渲染，行移位
② updateScroll → scrollDir=1 → scrollTick → 页面下滚
③ DOM 抖动 + 内容下移 → 鼠标现在在另一行 Z 上
④ 下一个 @dragover 在 Z 上触发 → rowReorderById(X,Z) → 撤销上次重排
⑤ scrollTick 继续滚 → 回到 ③ → ∞
```

来回跳动 = 重排被不断撤销/重做。
无法停止 = scrollDir 永远 1，没有机会被设为 0。

### 修复：调换顺序 + 滚动中跳过 reorder

```
改前：reorder → scroll
改后：scroll → reorder（仅当 scrollDir === 0）
```

| 文件 | 改前 | 改后 |
|------|------|------|
| `InboundList.vue:554-561` | `rowReorderById` → `updateScroll` | `updateScroll` → `if (scrollDir===0) rowReorderById` |
| `SubscriptionFormModal.vue:95-103` | `splice` → `subUpdateScroll` | `subUpdateScroll` → `splice` |

### 回退
- 恢复原始执行顺序

## 二十三、修复：scroll-distance → rAF 帧守卫（2026-05-17）

// 改前（scroll-distance）
if (el && Math.abs(el.scrollTop - lastReorderScrollTop) >= 44) {

  rowReorderById(…);

// 改后（rAF 帧守卫）
if (!reorderGuard) {
  rowReorderById(…);
  reorderGuard = true;
  requestAnimationFrame(() => { reorderGuard = false; });
}
```

|------|---------------|-----------|
| 跟随延迟 | 44px 滚动距离 | **0（逐帧）** |
| 死锁风险 | 有 | **无** |
| 容器依赖 | 需 `scrollContainerEl` | 无 |

## 二十六、速度曲线改为指数衰减：贴边慢、边界快（2026-05-17）

### 问题
原速度公式 `delay = 300 + 5000 × t³` 让**贴边最快、边界最慢**。用户移入触发区边界时速度只有 8px/s（几乎不动），以为没触发，继续往边缘推——然后 147px/s 突然冲出。

### 公式对比

```
改前：delay = 300 + 5000 × t³        （t=scrollDist/idleTrigger）
改后：delay = 300 + 2000 × (1-t)⁴     （指数衰减）
```

| t | scrollDist | 旧 delay | 新 delay | 旧速度 | 新速度 |
|---|-----------|---------|---------|-------|-------|
| 0 | 贴边 | 300ms | **2300ms** | 147px/s 🔥 | **19px/s ⏳** |
| 0.25 | 25% | 378ms | 630ms | 116px/s | 70px/s |
| 0.5 | 50% | 925ms | **425ms** | 48px/s | 104px/s |
| 0.75 | 75% | 2409ms | 308ms | 18px/s ⏳ | 143px/s |
| 1.0 | 边界 | 5300ms | **300ms** | 8px/s ⏳ | **147px/s 🔥** |

### 效果
- 贴边（t=0）：2300ms/行 → 19px/s，首 tick 仅 2.3 秒，立即感知页面在缓慢滚动
- 远离边界（t→1）：速度递增到 147px/s，快速跨行
- 慢速区从原来触发区后半段窄窄的 100px，扩大到整个前半段

### 文件改动

| 文件 | 行 | 改前 | 改后 |
|------|---|------|------|
| `InboundList.vue` | 480 | `300+5000*Math.pow(t,3)` | `300+2000*Math.pow(1-t,4)` |
| `SubscriptionFormModal.vue` | 70 | `300+5000*Math.pow(t,3)` | `300+2000*Math.pow(1-t,4)` |

- 生成的 JSON 包含字面换行符和缩进空格
- 当此字符串通过 `axios.post` 作为 JSON body 的 `settings` 字段发送时：
  ```
  {"id":123,"settings":"{\"clients\": [{\n  \"id\": \"uuid\",\n  \"email\": \"...\",\n  ...\n}]}"}
  ```
- Go 的 `c.ShouldBind` 解析 outer JSON 后，`data.Settings` 包含实际换行符
- `json.Unmarshal([]byte(data.Settings), &settings)` 在特定条件下无法正确解析多行 JSON

### 修复
三处 `client.toString()` 全部改为 `client.toString(false)`：

## 五十五、修复 toggleSelect 幂等性检查：next === has 消除 mount 循环（2026-05-19）

### 问题

function toggleSelect(client, next) {

}
```

## 四十二、修复 "malformed JSON" 根因：SQLite JSON_EACH(NULL) + 未保护的类型断言（2026-05-19）

### 问题
`AddInboundClient` 始终返回 `"Something went wrong (malformed JSON)"`。经过多轮调试发现两个独立的触发源：

**根因 1：SQLite JSON_EACH(NULL)**
`getAllEmailSubIDs()` 的 SQL 查询：
```sql
JSON_EACH(JSON_EXTRACT(inbounds.settings, '$.clients'))
```
在 wireguard（peers[]）、mixed/http（accounts[]）等不含 `"clients"` 键的入站存在时，`JSON_EXTRACT` 返回 NULL，`JSON_EACH(NULL)` 在 SQLite 中抛出 `"malformed JSON"` 错误。此错误通过 `checkEmailsExistForClients` → `AddInboundClient` 直接返回给前端。

该问题在纯 vmess/vless/trojan 环境中不可见，只有混合协议数据（如测试脚本创建的所有 10 种协议）时才会触发。

**根因 2：未保护的 `oldSettings["method"].(string)`**
`AddInboundClient` 在添加 shadowsocks 客户端时尝试读取 `oldSettings["method"]` 字符串。若该 key 不存在（nil），`nil.(string)` panic。

### 修复

| 修改 | 文件位置 | 说明 |
|------|---------|------|
| SQL 替换为 Go 迭代 | `web/service/inbound.go:getAllEmailSubIDs()` | 读入所有入站，用 `json.Unmarshal` + `map[string]any` 安全解析，忽略不含 `"clients"` 的入站 |
| 添加 `ok` 守卫 | `web/service/inbound.go:1144` | `oldSettings["method"].(string)` → `if m, ok := ... { cipher = m }` |

### 相关修复（本迭代中累积）
| 修复 | 文件 | 说明 |
|------|------|------|
| `toString(false)` | `ClientFormModal.vue`, `ClientBulkModal.vue`, `InboundsPage.vue` | 多行 JSON → 紧凑 JSON |

## 四十一、修复 ClientRowTable 多客户端被识别成一个（2026-05-19）

### 问题
在入站列表展开的客户端行中，如果入站有多个客户端，勾选一个客户端会把所有客户端一起勾选/取消，无法单独操作。

### 根因
`ClientRowTable` 使用 `client.clientId` 作为 `localSelected` Set 的唯一标识。当 settings JSON 缺少 `"clientId"` 字段时，所有客户端的 `clientId` 均为 `0`，`Set{0}` 只有一个条目，所有客户端共享同一个 key。

`rowKey()` 回退链 `email → id → password → JSON.stringify(client)` 确保每个客户端都有唯一标识。

### 修复
选中状态全面从 `client.clientId` 切换到 `rowKey(client)`：

| 受影响部分 | 修改内容 |
|-----------|---------|
| `localSelected` | 初始化和 watch 从 `c.clientId` 改 `rowKey(c)` |
| `isSelected` / `toggleSelect` / `selectAll` | key 从 `client.clientId` 改 `rowKey(client)` |
| `allSelected` / `someSelected` / `selectedCount` | 从 `local.has(c.clientId)` 改 `local.has(rowKey(c))` |
| `watch(clients)` 收敛 | 从 `list.map(c => c.clientId)` 改 `list.map(rowKey)` |
| `confirmBulkDelete` | 从 `local.has(c.clientId)` 改 `local.has(rowKey(c))` |
| `emitSelection()` | 通过 `rowKey` 筛选后 emit deduped `clientId[]` |

### 导出兼容性
`emitSelection()` 保持 emit deduped `clientId[]`，后端 `genInboundLinks(selectedClientIds)` 无需修改。当 `clientId` 全部为 `0` 时 partial selection 降级为全选——可接受，`ensureClientIdsInSettings` 在首次保存后分配唯一 `clientId`。

### 验证
- API 测试：入站列表正常返回 50 条数据
- 代码审查：`rowKey()` 对 `email`/`id`/`password` 唯一性满足预期

## 五十八、修复导出订阅时多客户端入站选中丢失 + email→clientId 转换（2026-05-21）

### 问题
勾选多客户端入站的某个客户端 + 单客户端入站的行 checkbox，点击工具栏"导出订阅链接"，只有单客户端入站出现在已选面板。

### 根因
1. `selectedClientIds` 存的是 email 字符串，但订阅表单需要数字 `clientId`。直接拼接 `"id:email"` 导致 `parseInt(email) → NaN`。
2. `onClientSelectionChange` 只更新 `selectedClientIds`，未同步更新 `selectedIds`。

### 修复
1. `onClientSelectionChange`：ids 非空时同步将 inboundId 加入 `selectedIds`
2. `exportAllSubs`：从 `dbInbounds.settings` 构建 `emailToClientId` 映射，遍历时通过 email 查到数字 clientId

### 文件清单
| 文件 | 改动 |
|------|------|
| `frontend/src/pages/inbounds/InboundsPage.vue` | `onClientSelectionChange` + `exportAllSubs` |

### 回退
1. 恢复 `onClientSelectionChange` 旧版
2. 恢复 `exportAllSubs` 旧版
